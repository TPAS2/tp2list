# TP2List — project notes

## What it is
A single-file `index.html` personal organizer. No build step, no backend.
Hosted on GitHub Pages (moved from Netlify after its free tier became credit-limited).
Cross-device sync (laptop ↔ phone) uses a **sync code** via Firebase Realtime Database (`FB_DB` in index.html,
project `tp2-list`). The There is no separate refresh button: syncing is automatic (on open, when you return to the app, when the connection comes back, and live while open) and the sheet has a **Sync now** button. The Sync button opens a sheet: "Get a sync code" uploads this device's data, and the other device enters
the 10-character code, after which the synced copy replaces its data. Data is stored at `/sync/<CODE>/sections/<field>` = `{v: JSON text, t: edit time}`,
one entry per top-level field of `data`, so new fields sync automatically. Sections merge independently and the newest edit wins.
Live updates come via EventSource. Remote changes wait while an input is focused. Local state is kept in `tpas2:fb:code` / `tpas2:fb:state`.
JSONBin has been removed entirely. Firebase sync codes are the only sync; a device without a code just keeps its data locally.
Works offline: `sw.js` (service worker) caches the app. Edits save locally and sync when back online.
Firebase rules (must include both):
`{"rules":{"lists":{"$code":{".read":true,".write":true}},"sync":{"$code":{".read":"$code.length >= 10",".write":"$code.length >= 10"}}}}`
Bump `CACHE` in `sw.js` if a cached version ever gets stuck.

## Structure
Swipeable pages, all sized the same: **List, Calendar, ETracker**, plus **Business** and **Other** as full-page views opened from the nav buttons.
Phone and desktop use the same layout: one page at a time with swipe/tap navigation (the old desktop two-column layout was removed).

- **List**: task list (shows nothing when empty: no placeholder text or divider) → Other button → Today widget (items scheduled today in Calendar; ticking one removes it)
  → Overdue (missed calendar items, red date badges, tap to jump to that date).
  Today/Overdue collapse to a bare `(0)` when empty.
- **Calendar**: Monday-first month grid with touching day cells (thin dividing lines, no gaps) that fill the full width, ~54px tall on phones and 64px on laptops; one-off, recurring and multi-day events; notes via a highlighter-style tag;
  repeat patterns including biweekly; dates, times and repeat rules can be edited after creation.
- **ETracker** (expenses; tab and page title renamed from "Expenses", data still `data.expenses`): euro-based; defaults to today's entries in time order; "ALL DETAILS" shows the whole month by date+time.
  A positive monthly balance rolls into the next month.
- **Other** (Notes-style): one slim bar at the top-left with ← Back, the title and the SL / 🎂 Birthdays shortcut buttons on the right (bright gradient pills with a glowing outline; always visible, takes almost no space; wraps to a second row on very narrow screens).
  Below, a two-pane view: left = names of your lists (new-list box on top; ⠿ handle drags to reorder; each row shows the first line as a preview), right = the selected list as a big title (tap to rename, ✕ deletes, confirms if it has content)
  and one text box, one item per line, blank lines kept (lines are parsed back into `items` on input; unchanged lines keep id/done). The selected list is remembered per device (`tpas2:other:sel`).
  **Photos** on a list: paste an image into the text box (or tap 📷 in the list's header) and it's shrunk (max 1200px, JPEG) and kept in `r.images = [{id, img: dataURL}]`, shown as thumbnails above the text (tap = full screen, ✕ = remove, with a confirm). They sync with the list. Photos are skipped in safety copies (`takeSafetyCopy` blanks `img`) but included in downloaded backups; a photo is refused when all data would pass ~4.2 MB (localStorage limit).
  On phones (<700px) it's drill-down like the Notes app: the names fill the screen, tapping one opens it full screen with a "‹ Lists" link (`otherNoteOpen`, `#otherPage.note-open`).
- **Business** (nav button before Other, `#businessPage`, data `data.businessTabs` = `[{id, name}]`): a Google-Sheets-style tab strip along the bottom with 7 sections, seeded once as "Section 1…7" (ids biz1…biz7; names are generic on purpose so no real business names live in the public source). `+` adds a section; tabs can be dragged sideways to reorder (mouse: drag; touch: press and hold, then drag; `startBizTabDrag`); each tab's ▾ menu has Rename / Move left / Move right / Delete. Selected tab is per device (`tpas2:biz:sel`). Each section has a `type`: unset shows a chooser (**Spreadsheet** or **Notes**); the ▾ menu can switch between them (data is kept both ways).
  **Spreadsheet** (`tab.sheet = {rows, cols, cells: {'A1': 'text or =formula'}}`, default 14 rows × 12 cols (no minimum row count, min 1; you can delete columns down to 1 and the remaining ones stretch to fill the page); all columns (no cap at L; min 10px each) and rows 1–14 are fitted to the panel by default and scrollbars are hidden whenever the whole sheet fits (`updateScroll`), max 2000 rows × 52 columns; big sheets build the first 80 rows at once and the rest in background chunks (`FIRST_ROWS`/`buildRow`/`bizRenderToken`) and use `table-layout: fixed` (`.sheet-grid.fixed`, widths all explicit) so typing stays responsive — about 0.3 s per keystroke at 2000 rows × 12 columns; `showCell` skips unchanged cells; code that touches `inputs[ref]` must tolerate rows that aren't built yet): tap-to-edit cells (Enter/↓/↑ move between rows; ←/→ move between cells when the caret is at that edge of the text or the whole text is selected, but not while the caret is inside a formula), + / − Row and Column buttons, sticky headers, scrolls inside its panel; the focused cell's highlight fills the whole cell.
  Formulas (`sheetCell`): `=A1+B1`, + − * / ( ), `SUM AVERAGE(AVG) MIN MAX COUNT` over cells/ranges like `A1:A5`; errors show `#ERR`, circular references `#CIRC`; the formula shows while editing, the result otherwise. **Notes** (`tab.text`): a plain text box.
  **Spreadsheet import/export + formatting** (all spreadsheet buttons sit in one wrapping row beside the section name: rows/columns, formatting, formula hint is the ⓘ tooltip; **Import / Export sit in the top bar on the same row as the "Business" title**, at the right, and only show for spreadsheet sections): **Import** reads .xlsx (formulas kept as `=...`, shared formulas expanded, dates → ISO text, percentages, bold/italic/size/align/fills/text colours/borders, extra sheets offered as new sections) and CSV/TSV (values only); **Export** writes .xlsx with formulas, cached values and styles (our own ZIP writer; reading uses `DecompressionStream`). Max 2000 rows × 52 cols (extra is truncated with an alert); a `'before import'` safety copy is taken first. Formulas use a real parser (`sheetParse`/`sheetEval`: IF, ROUND, SUMIF, COUNTIF, VLOOKUP, `&`, `$A$1`, `A:A`, …); functions it can't run fall back to the file's cached value (`sheet.cache`, shown italic, `#UNSUP` otherwise). **Copy / cut / paste inside the app** (Cmd/Ctrl + C / X / V on the selected block, document-level listeners via `bizSheetClip`): formulas shift like Google Sheets, and formatting (bold, colours, borders, number format, merges for a same-size paste) comes along; a single copied cell pastes into every selected cell; cut also clears the source. It works by remembering the last copy (`bizLastCopy`) and recognising its text on the clipboard; text copied elsewhere pastes as plain values (below). **Paste from Google Sheets / Excel**: copy cells there, click a cell here and paste; the tab-separated block fills from the selected cell (grid grows up to the caps; values only, as the clipboard carries no formulas; a `'before paste'` safety copy is taken). **Formula bar** (`.fx-bar` in the Business title row, between the title and Import/Export; wraps to its own line on phones): shows the selected cell's name and raw contents (formula text) and edits it; typing in the bar or in the cell mirrors to the other, autocomplete and point-and-click work in it, Enter commits and moves down, Esc reverts; A1 is selected by default. The Business page uses tighter spacing above the grid (`body:has(#businessPage.active) header` etc.) so more rows show. **Light mode**: the grid is plain white with grey lines and light grey headers (`html[data-theme="light"] .sheet-grid …` rules); cell fills you choose still win. **Other sections in formulas**: `='Section 2'!B3-A1`, `=SUM(Sales!A1:A5)` (section name, case-insensitive; quote names with spaces) read cells of other spreadsheet sections (`sheetByName`, `sheetResolve`; memo/`seen` keys include the sheet id so cross-section cycles give `#CIRC`; unknown name → `#NAME?` or the imported cached value). Section names with spaces also work unquoted (`=Section 1!A1`; `sheetNames`). **Click across tabs**: while typing a formula (caret after `=`/operator/`(`/`,`), press another spreadsheet tab, click a cell (or drag a range) there, and the reference (`'Name'!A1:B2`) is inserted and you jump back to the cell you were editing with the caret after it (`bizFormulaState`/`bizPending`/`bizFinishPick`; Cancel button, Esc, or pressing the original tab cancels and keeps the typed text). Limits: renaming a section or deleting rows/columns does not rewrite formulas in *other* sections that point at it. **Point-and-click formulas**: while a cell is being edited as `=…` and the caret follows an operator, `(`, `,` or `=`, clicking another cell inserts its reference, dragging inserts a range (`A1:A3`), and clicking again replaces the reference just inserted (`pickAllowed`/`putRef`, picked cells get a dashed outline). Typing anything ends the pick; otherwise clicks move between cells as normal. **Formula autocomplete**: typing a function name after `=` pops up matching functions with their arguments (`SHEET_FUNCS`, `fnPopUpdate`; ↑/↓ choose, Tab or a tap inserts `NAME(`, Enter inserts only a suggestion picked with ↑/↓ and otherwise saves the formula as typed (`fnPopNav`), Esc closes). Keep `SHEET_FUNCS` in step with `sheetFn` when adding functions. **Array formulas**: a range inside a formula is an array (`SheetArray`); operators and one-value functions (`SHEET_LIFT`, `IF`, `IFERROR`) work on every element (`sLift`), aggregates accept arrays (`=SUM(IFERROR(REGEXEXTRACT(F31:F40,"(\d+)$"),0))`), `ARRAYFORMULA(x)` passes through, `SUMPRODUCT` multiplies then adds; a formula that returns an array shows its first value and **spills** the rest into the empty cells below/right (display only; `sheetSpillMap`, tried in a scratch memo; if a target cell holds data the formula shows `#REF!`; spilled cells can be referenced by other formulas but a spilling formula can't itself read spilled cells). Text-pulling functions: `LEFT RIGHT MID FIND SEARCH SUBSTITUTE TEXTBEFORE TEXTAFTER VALUE REGEXEXTRACT REGEXMATCH REGEXREPLACE` (e.g. the number at the end of a cell: `=IFERROR(REGEXEXTRACT(A2,"(\d+)$"),0)`; a number-looking REGEXEXTRACT result becomes a number like in Sheets; no `SPLIT`, which would need to fill several cells). **Merge cells**: select a block and press ⊞ Merge (press again on the same block to unmerge); stored as `sheet.merges = [{r1, c1, r2, c2}]` (rows 1-based, cols 0-based), rendered with colspan/rowspan, covered cells are hidden but keep their data; imported from / exported to .xlsx `mergeCells`. **Right-click** a cell, column letter or row number (long-press on touch): set an exact width/height in px (applies to every selected column/row), fit to data, reset, merge. The right-click menu also has **Insert row above / below** and **Insert column left / right** (as many as are selected; `sheetInsertLines` shifts cells, formatting, sizes, merges and formula references, and a range that spans the new line grows) and **Delete row(s) / column(s)** (confirms, takes a `'before delete'` safety copy, shifts cells/formatting/sizes/merges up or left and rewrites formula references; refs to deleted cells become `#REF!`; `sheetDeleteLines`). **Cmd/Ctrl-click** a column letter, row number or cell adds another range to the selection (`extra` ranges; the cell `focus` handler must not reset the selection while `extra` is set — this once broke cell Cmd-click), so formatting, sizes and delete apply to all of them. **Double-click** the edge of a column/row header fits it to the data (widest text / tallest font). Columns can be as narrow as 10px (rows min 24px; the auto-fit default stays at least 64px so phones scroll sideways). Column widths / row heights: drag the right edge of a column letter or the bottom edge of a row number (works by touch); double-click fits to data. Stored as `sheet.colW[c]` / `sheet.rowH[r]` in px (not exported to .xlsx). Per-cell format `sheet.fmt[ref] = {a, b, i, s, bg, fg, bd, nf}`; `nf` is the number format chosen from the **123 ▾** dropdown (`SHEET_NUMFMTS`: Automatic, Number, Whole number, Euro, Pound, Dollar, Percent; `sheetFormatNumber`): it only changes what's displayed when the cell isn't being edited (the stored value stays raw), and is imported from / exported to .xlsx number formats. Other format keys: set from a toolbar (B / I / − size + / align L C R / 123 ▾ / Fill / Text / Borders) on the selection; borders are drawn inside each cell (`bd` letters l/r/t/b) and every edge is drawn by exactly one cell so lines line up (`paintCell`): a cell draws its right/bottom edge if it has one or the cell(s) to its right/below want a left/top edge there, and left/top edges are only drawn on the first column/row; merged blocks count as one cell on both sides; `apply` and the Merge button repaint the neighbours (drag, shift-click, row/column header). LibreOffice is broken in the sandbox, so import/export was tested with a hand-built .xlsx and an export → import round-trip.
  **Car reselling** (`type: 'cars'`, `tab.cars = {vehicles: [{id, name, bought, sold, expenses: [{id, desc, amount}]}], notes}`, euros): add vehicles (newest first), split into **Current cars** (no sale price yet; header shows the total invested) and **Sold cars** (header shows the total profit); a car moves to Sold when its sale price is entered and the field is left (clearing the price moves it back). Each vehicle is a collapsible card with Bought for, a list of expenses (description + amount), and Sale price. Cost = bought + expenses; profit = sale − cost, shown once a sale price is entered (header shows `Not sold · cost` until then). The look is deliberately minimal: soft filled blocks (`--fill`) instead of outlines, few divider lines. Each vehicle's **Name** is editable inside its card, and a **Renting** block takes `rentPerMonth` plus either a typed `rentMonths` or dates `rentStart` / optional `rentEnd` (`YYYY-MM-DD`): with a start date the months rented are worked out automatically — every month that has started, from the start date to the end date (or to today while there is no end date or it hasn't passed yet), so the first month counts straight away and each new month adds one on its start-date day (`carRentMonths`), so rent income keeps growing by itself until the end date (rental income = per month × months; added to profit: profit = sale + rent − cost; an unsold car shows `Rent €X · cost`). The totals bar has a **Rent income** box, and total profit = profit on sold cars + rent already earned on unsold cars − other expenses. Each vehicle also has its own Notes box (`v.notes`) at the bottom of its card. **Other expenses** (`cars.otherExpenses = [{id, desc, amount}]`): a section under the vehicles for costs not tied to one car (fuel, adverts, insurance…), with its own total.
  Totals bar: total spent (all vehicle costs + other expenses), total sales, other expenses, and total profit = profit on sold cars − other expenses (the "Sold cars" header shows profit on cars alone). A Notes box sits under everything. All Business notes boxes (page notes, vehicle notes, Notes-type sections) auto-grow to fit their text (`autoGrow`), so they never scroll inside; the page/panel scrolls instead. Section 2 (`biz2`) is set to this type by default and renamed "Car Reselling" if it still has its default name; any section can switch to it from the ▾ menu.
- **Birthdays** (opened from Other, stored as `data.birthdays` = `{id, name, date: 'MM-DD'}`, no year; old 'YYYY-MM-DD' entries still work): simple list sorted by next upcoming
  birthday, showing date and "Today / Tomorrow / N days". Add with name + day + month; Enter in any field adds. On the day, it also shows at the top of the List page's Today widget (🎂, tick box); ticking sets `doneYear` so it hides until next year. Not a calendar event. The Other card shows the next one.
- **Stock / SL** (`stock/index.html`, opened from the SL card on the Other page; no longer in the main nav): separate home-stock + shopping list app.
  Items have an emoji icon (auto-guessed from the name, or picked by hand), qty, low threshold (no category or unit fields in the editor);
  each item is at Home or Apartment; three tabs At Home / At Apartment / To Buy, set via the "List" dropdown in the editor (To Buy = qty 0; the item keeps its place for when it is restocked). No category filter chips. QR/barcode scan to find or add items (BarcodeDetector, falls back to vendored jsQR),
  printable QR labels per item. Items show as a compact list (one row each: icon, name, LOW tag, − qty +). Stored in IndexedDB on the device; JSON export/import in the menu.
  **Sharing** is separate from TP2List's own sync code: "Share" gives a 6-character code, and other phones join by typing it.
  The code is remembered on each phone (`tp2stock:share:code`). The header button shows "Synced" (not the code) once joined; the code is shown inside the Share sheet. Backend is a Firebase Realtime Database
  (REST + EventSource, no SDK) at `/lists/<CODE>/{created,items/<id>,deleted/<id>}`, set via `SHARE_DB` in stock/index.html (project `tp2-list`, europe-west1).
  The Share button stays hidden while `SHARE_DB` is empty. Merge is per item, newest `updated` wins, and deletions are timestamped.
  Firebase rules: `{"rules":{"lists":{"$code":{".read":true,".write":true}}}}` (root stays unreadable, so codes can't be listed).
- **Light / dark mode**: a ☀ / ☾ button in the header (`#themeBtn`) switches `html[data-theme="light"|"dark"]`; the choice is saved per device in `tpas2:theme` (default dark), applied by a tiny inline script in `<head>` before first paint (no flash), and `stock/index.html` follows the same key. ## Backups & safety copies (Sync sheet → "Backup")
- **Backup now** saves a safety copy immediately (reason `manual`). **Download backup** saves all data as `tp2list-backup-YYYY-MM-DD.json` (`{app:'tp2list', version:1, exportedAt, data}`); **Restore from file…** replaces this device's data with it (confirms first, then queues it for sync; the ↩ undo button can step back).
- **Backup reminder** (`updateBackupNudge`, `#backupNudge` under the header): appears when there is data and no backup was downloaded for 7+ days (`tpas2:lastBackup`; "Later" snoozes a day via `tpas2:nudgeSnooze`), and a red warning appears whenever localStorage use passes ~4 million characters (browser limit is ~5 million).
- **Safety copies** (`tpas2:safety` in localStorage, newest 8, skipped when the data is empty): automatically one a day on open (`daily`), just before a sync update replaces local data (`before sync update`; always on the first sync after joining, otherwise at most every 15 min), and before any restore (`before restore`). The dropdown + Restore button brings one back. Functions: `takeSafetyCopy`, `restoreData`, `fillSafetyList`.
- Known limit: sync merges per top-level section with newest edit wins, so editing the same section (e.g. Business, which is one section) on two devices at once can drop one device's changes. The safety copy is the net for that.

## Past bugs (fixed — check here first if something looks off)
- Sheets with more than 80 rows stopped at row 80: the row-height fitting loop touched rows that the chunked build hadn't created yet and threw, aborting the render. Any code that loops over `sh.rows` while the grid is built in chunks must stay within `FIRST_ROWS` or guard `rowTh[r]` / `inputs[ref]`.
- A single-quoted JS string containing `'Section 2'` (in the spreadsheet ⓘ tooltip) broke the whole page script for one merge. Always run a syntax check on the page script (extract `<script>` and `node --check`) before merging.
- Sync pull rebuilt data without `ledger`/`spanEvents`, wiping them on every pull.
- Sync push never updated the local timestamp, so the app treated its own saved data as stale and
  overwrote it with an old server copy. (Historical: JSONBin era.)
- Real business data was once hardcoded in the source. It has been removed, but it may still exist in old git history.
- Stray CSS brace, hidden `.stamp-mark` reserving layout space, and a background-color rule blocking the glow.

## Rules
- Always merge when done: once a change is made and tested, open a PR and merge it into `main` without asking (the user authorized this). Main deploys to GitHub Pages.
- Never hardcode real business data (invoice names/amounts) in the source.
- Any sync change must preserve every data field (`ledger`, `spanEvents`, etc.) and keep timestamps consistent.
