# TP2List — project notes

## What it is
A single-file `index.html` personal organizer. No build step, no backend.
Hosted on GitHub Pages (moved from Netlify after its free tier became credit-limited).
Cross-device sync (laptop ↔ phone) uses a **sync code** via Firebase Realtime Database (`FB_DB` in index.html,
project `tp2-list`). The There is no separate refresh button: syncing is automatic (on open, when you return to the app, when the connection comes back, and live while open) and the sheet has a **Sync now** button. The Sync button opens a sheet: "Get a sync code" uploads this device's data, and the other device enters
the 10-character code, after which the synced copy replaces its data. Data is stored at `/sync/<CODE>/sections/<field>` = `{v: JSON text, t: edit time}`,
one entry per top-level field of `data`, so new fields sync automatically. Sections merge independently and the newest edit wins.
Live updates come via EventSource. Remote changes wait while an input is focused. Local state is kept in `tpas2:fb:code` / `tpas2:fb:state`.
JSONBin has been removed entirely. Firebase sync codes are the only sync; a device without a code just keeps its data locally.
Works offline: `sw.js` (service worker) caches the app. Edits save locally and sync when back online.
Firebase rules (must include both):
`{"rules":{"lists":{"$code":{".read":true,".write":true}},"sync":{"$code":{".read":"$code.length >= 10",".write":"$code.length >= 10"}}}}`
Bump `CACHE` in `sw.js` if a cached version ever gets stuck.

## Structure
Swipeable pages, all sized the same: **List, Calendar, ETracker**, plus **Business** and **Other** as full-page views opened from the nav buttons.
Phone and desktop use the same layout: one page at a time with swipe/tap navigation (the old desktop two-column layout was removed).

- **List**: task list (shows nothing when empty: no placeholder text or divider) → Other button → Today widget (items scheduled today in Calendar; ticking one removes it)
  → Overdue (missed calendar items, red date badges, tap to jump to that date).
  Today/Overdue collapse to a bare `(0)` when empty.
- **Calendar**: Monday-first month grid with touching day cells (thin dividing lines, no gaps) that fill the full width, ~54px tall on phones and 64px on laptops; one-off, recurring and multi-day events; notes via a highlighter-style tag;
  repeat patterns including biweekly; dates, times and repeat rules can be edited after creation.
- **ETracker** (expenses; tab and page title renamed from "Expenses", data still `data.expenses`): euro-based; defaults to today's entries in time order; "ALL DETAILS" shows the whole month by date+time.
  A positive monthly balance rolls into the next month.
- **Other** (Notes-style): one slim bar at the top-left with ← Back, the title and the SL / 🎂 Birthdays shortcut buttons on the right (bright gradient pills with a glowing outline; always visible, takes almost no space; wraps to a second row on very narrow screens).
  Below, a two-pane view: left = names of your lists (new-list box on top; ⠿ handle drags to reorder; each row shows the first line as a preview), right = the selected list as a big title (tap to rename, ✕ deletes, confirms if it has content)
  and one text box, one item per line, blank lines kept (lines are parsed back into `items` on input; unchanged lines keep id/done). The selected list is remembered per device (`tpas2:other:sel`).
  **Photos** on a list: paste an image into the text box (or tap 📷 in the list's header) and it's shrunk (max 1200px, JPEG) and kept in `r.images = [{id, img: dataURL}]`, shown as thumbnails above the text (tap = full screen, ✕ = remove, with a confirm). They sync with the list. Photos are skipped in safety copies (`takeSafetyCopy` blanks `img`) but included in downloaded backups; a photo is refused when all data would pass ~4.2 MB (localStorage limit).
  On phones (<700px) it's drill-down like the Notes app: the names fill the screen, tapping one opens it full screen with a "‹ Lists" link (`otherNoteOpen`, `#otherPage.note-open`).
- **Business** (nav button before Other, `#businessPage`, data `data.businessTabs` = `[{id, name}]`): a Google-Sheets-style tab strip along the bottom with 7 sections, seeded once as "Section 1…7" (ids biz1…biz7; names are generic on purpose so no real business names live in the public source). `+` adds a section; tabs can be dragged sideways to reorder (mouse: drag; touch: press and hold, then drag; `startBizTabDrag`); each tab's ▾ menu has Rename / Move left / Move right / Delete. Selected tab is per device (`tpas2:biz:sel`). Each section has a `type`: unset shows a chooser (**Spreadsheet** or **Notes**); the ▾ menu can switch between them (data is kept both ways).
  **Spreadsheet** (`tab.sheet = {rows, cols, cells: {'A1': 'text or =formula'}}`, default 14 rows × 12 cols (no minimum row count, min 1; you can delete columns down to 1 and the remaining ones stretch to fill the page); all columns (no cap at L; min 10px each) and rows 1–14 are fitted to the panel by default and scrollbars are hidden whenever the whole sheet fits (`updateScroll`), max 2000 rows × 52 columns; big sheets build the first 80 rows at once and the rest in background chunks (`FIRST_ROWS`/`buildRow`/`bizRenderToken`) and use `table-layout: fixed` (`.sheet-grid.fixed`, widths all explicit) so typing stays responsive — about 0.3 s per keystroke at 2000 rows × 12 columns; `showCell` skips unchanged cells; code that touches `inputs[ref]` must tolerate rows that aren't built yet): tap-to-edit cells (Enter/↓/↑ move between rows; ←/→ move between cells when the caret is at that edge of the text or the whole text is selected, but not while the caret is inside a formula), + / − Row and Column buttons, sticky headers, scrolls inside its panel; the focused cell's highlight fills the whole cell.
  Formulas (`sheetCell`): `=A1+B1`, + − * / ( ), `SUM AVERAGE(AVG) MIN MAX COUNT` over cells/ranges like `A1:A5`; errors show `#ERR`, circular references `#CIRC`; the formula shows while editing, the result otherwise. **Notes** (`tab.text`): a plain text box.
  **Spreadsheet import/export + formatting** (all spreadsheet buttons sit in one wrapping row beside the section name: rows/columns, formatting, formula hint is the ⓘ tooltip; **Import / Export sit in the top bar on the same row as the "Business" title**, at the right, and only show for spreadsheet sections): **Import** reads .xlsx (formulas kept as `=...`, shared formulas expanded, dates → ISO text, percentages, bold/italic/size/align/fills/text colours/borders, extra sheets offered as new sections) and CSV/TSV (values only); **Export** writes .xlsx with formulas, cached values and styles (our own ZIP writer; reading uses `DecompressionStream`). Max 2000 rows × 52 cols (extra is truncated with an alert); a `'before import'` safety copy is taken first. Formulas use a real parser (`sheetParse`/`sheetEval`: IF, ROUND, SUMIF, COUNTIF, VLOOKUP, `&`, `$A$1`, `A:A`, …); functions it can't run fall back to the file's cached value (`sheet.cache`, shown italic, `#UNSUP` otherwise). **Copy / cut / paste inside the app** (Cmd/Ctrl + C / X / V on the selected block, document-level listeners via `bizSheetClip`): formulas shift like Google Sheets, and formatting (bold, colours, borders, number format, merges for a same-size paste) comes along; a single copied cell pastes into every selected cell; cut also clears the source. It works by remembering the last copy (`bizLastCopy`) and recognising its text on the clipboard; text copied elsewhere pastes as plain values (below). **Paste from Google Sheets / Excel**: copy cells there, click a cell here and paste; the tab-separated block fills from the selected cell (grid grows up to the caps; values only, as the clipboard carries no formulas; a `'before paste'` safety copy is taken). **Formula bar** (`.fx-bar` in the Business title row, between the title and Import/Export; wraps to its own line on phones): shows the selected cell's name and raw contents (formula text) and edits it; typing in the bar or in the cell mirrors to the other, autocomplete and point-and-click work in it, Enter commits and moves down, Esc reverts; A1 is selected by default. The Business page uses tighter spacing above the grid (`body:has(#businessPage.active) header` etc.) so more rows show. **Light mode** (the whole app: white background and panels, near-black text, darker lines, via the `html[data-theme="light"]` variables): the grid is plain white with grey lines and light grey headers (`html[data-theme="light"] .sheet-grid …` rules); cell fills you choose still win. **Other sections in formulas**: `='Section 2'!B3-A1`, `=SUM(Sales!A1:A5)` (section name, case-insensitive; quote names with spaces) read cells of other spreadsheet sections (`sheetByName`, `sheetResolve`; memo/`seen` keys include the sheet id so cross-section cycles give `#CIRC`; unknown name → `#NAME?` or the imported cached value). Section names with spaces also work unquoted (`=Section 1!A1`; `sheetNames`). **Click across tabs**: while typing a formula (caret after `=`/operator/`(`/`,`), press another spreadsheet tab, click a cell (or drag a range) there, and the reference (`'Name'!A1:B2`) is inserted and you jump back to the cell you were editing with the caret after it (`bizFormulaState`/`bizPending`/`bizFinishPick`; Cancel button, Esc, or pressing the original tab cancels and keeps the typed text). Renaming a section, or inserting / deleting its rows or columns, rewrites the formulas in *other* sections that point at it (`sheetFixOtherRefs` at the end of `sheetInsertLines` / `sheetDeleteLines`, and `sheetRenameRefs` after Rename); a reference to a deleted cell becomes `#REF!`. Lowercase references (`=sum(a1:a5)`) shift like uppercase ones. **New rows copy the format and height of the row above**: Insert rows above passes the row above as `src`, Insert rows below the selected row, and the **+ Row** button calls `sheetInsertLines(sh, 'r', rows + 1, 1, rows)` so the new last row copies the old last row (columns still copy the clicked column). **Point-and-click formulas**: while a cell is being edited as `=…` and the caret follows an operator, `(`, `,` or `=`, clicking another cell inserts its reference, dragging inserts a range (`A1:A3`), and clicking again replaces the reference just inserted (`pickAllowed`/`putRef`, picked cells get a dashed outline). Typing anything ends the pick; otherwise clicks move between cells as normal. **Formula autocomplete**: typing a function name after `=` pops up matching functions with their arguments (`SHEET_FUNCS`, `fnPopUpdate`; ↑/↓ choose, Tab or a tap inserts `NAME(`, Enter inserts only a suggestion picked with ↑/↓ and otherwise saves the formula as typed (`fnPopNav`), Esc closes). Keep `SHEET_FUNCS` in step with `sheetFn` when adding functions. **Array formulas**: a range inside a formula is an array (`SheetArray`); operators and one-value functions (`SHEET_LIFT`, `IF`, `IFERROR`) work on every element (`sLift`), aggregates accept arrays (`=SUM(IFERROR(REGEXEXTRACT(F31:F40,"(\d+)$"),0))`), `ARRAYFORMULA(x)` passes through, `SUMPRODUCT` multiplies then adds; a formula that returns an array shows its first value and **spills** the rest into the empty cells below/right (display only; `sheetSpillMap`, tried in a scratch memo; if a target cell holds data the formula shows `#REF!`; spilled cells can be referenced by other formulas but a spilling formula can't itself read spilled cells). Text-pulling functions: `LEFT RIGHT MID FIND SEARCH SUBSTITUTE TEXTBEFORE TEXTAFTER VALUE REGEXEXTRACT REGEXMATCH REGEXREPLACE` (e.g. the number at the end of a cell: `=IFERROR(REGEXEXTRACT(A2,"(\d+)$"),0)`; a number-looking REGEXEXTRACT result becomes a number like in Sheets; no `SPLIT`, which would need to fill several cells). **Fill handle** (`.fill-handle`, small square at the bottom-right corner of the selected block; `fillSeries`): drag it down / up / right / left to continue the block like Google Sheets — two or more numbers continue as a series (1, 2 → 3, 4 …), a single number copies, text ending in a number counts up (`Item 1` → `Item 2`), formulas are copied with relative references shifted, other text repeats, and formatting is copied; the pointer near the sheet edge auto-scrolls so a long fill is possible, the filled range becomes the selection (`bizSelRestore`). **Drag-selecting** cells also auto-scrolls when the pointer is near / beyond the edge of the sheet (the pointer position is clamped to the sheet when looking up the cell under it). **Merge cells**: select a block and press ⊞ Merge (press again on the same block to unmerge); stored as `sheet.merges = [{r1, c1, r2, c2}]` (rows 1-based, cols 0-based), rendered with colspan/rowspan, covered cells are hidden but keep their data; imported from / exported to .xlsx `mergeCells`. **Right-click** a cell, column letter or row number (long-press on touch): set an exact width/height in px (applies to every selected column/row), fit to data, reset, merge. The right-click menu also has **Insert rows above… / below…** and **Insert columns left… / right…** (they ask how many; the box starts at the number of rows/columns selected, limited by the sheet maximum; `sheetInsertLines` shifts cells, formatting, sizes, merges and formula references, and a range that spans the new line grows; the new rows/columns copy the formatting and size of the row/column you right-clicked (`src`), and the sheet keeps its scroll position through `redrawKeep`/`bizScrollRestore`, which every structural change (insert, delete, +/− row/column, paste, cut) uses instead of a plain re-render) and **Delete row(s) / column(s)** (confirms, takes a `'before delete'` safety copy, shifts cells/formatting/sizes/merges up or left and rewrites formula references; refs to deleted cells become `#REF!`; `sheetDeleteLines`). **Cmd/Ctrl-click** a column letter, row number or cell adds another range to the selection (`extra` ranges; the cell `focus` handler must not reset the selection while `extra` is set — this once broke cell Cmd-click), so formatting, sizes and delete apply to all of them. **Double-click** the edge of a column/row header fits it to the data (widest text / tallest font). Columns can be as narrow as 10px (rows min 24px; the auto-fit default stays at least 64px so phones scroll sideways). Column widths / row heights: drag the right edge of a column letter or the bottom edge of a row number (works by touch); double-click fits to data. Stored as `sheet.colW[c]` / `sheet.rowH[r]` in px (not exported to .xlsx). Per-cell format `sheet.fmt[ref] = {a, b, i, s, bg, fg, bd, nf}`; `nf` is the number format chosen from the **123 ▾** dropdown (`SHEET_NUMFMTS`: Automatic, Number, Whole number, Euro, Pound, Dollar, Percent; `sheetFormatNumber`): it only changes what's displayed when the cell isn't being edited (the stored value stays raw), and is imported from / exported to .xlsx number formats. Other format keys: set from a toolbar (B / I / − size + / align L C R / 123 ▾ / Fill / Text / Borders) on the selection; borders are drawn inside each cell (`bd` letters l/r/t/b) and every edge is drawn by exactly one cell so lines line up (`paintCell`): a cell draws its right/bottom edge if it has one or the cell(s) to its right/below want a left/top edge there, and left/top edges are only drawn on the first column/row; merged blocks count as one cell on both sides; `apply` and the Merge button repaint the neighbours (drag, shift-click, row/column header). LibreOffice is broken in the sandbox, so import/export was tested with a hand-built .xlsx and an export → import round-trip.
  **Car reselling** (`type: 'cars'`, `tab.cars = {vehicles: [{id, name, bought, sold, expenses: [{id, desc, amount}]}], notes}`, euros): add vehicles (newest first), split into **Current cars** (no sale price yet; header shows the total invested) and **Sold cars** (header shows the total profit); a car moves to Sold when its sale price is entered and the field is left (clearing the price moves it back). The look is deliberately minimal: soft filled blocks (`--fill`) instead of outlines, few divider lines. Old days that had separate `trips`/`expenses` lists are merged on open (`txMigrate`; the removed `paid` lists are dropped). Clicking a date selects it and its card shows **under the calendar** (the calendar, totals and the blocks below stay visible; the old full-screen single-day view was switched off via `dayView = false`). Under the calendar (month view only): **Other expenses** and **Shell payable** (dated entries, every entry listed and totalled **all time**), **Credit notes** (running list with a total, not part of profit); these three are **drop-down boxes** (tap the heading to open/close, ▸/▾ arrow, closed by default, the heading keeps showing the total; state per device in `tpas2:tx:drop:<sectionId>:<otherExpenses|shell|credit>`, helper `drop`) and a **Notes** box. The totals bar: this month — Income, Expenses, Profit this month (= income − expenses), Not settled (income of days with trips that aren't settled); all time — Other expenses, Shell payable and **Net P/L** (= all income − all expenses − other expenses − Shell payable, like the sheet's NET P/L).   **Card payments** (trip entries have `card: true`, toggled with the magenta **Card** button on the row; set automatically when the description contains "card", also for imports/pictures and once for existing entries via `tx.cardDone`): the customer paid by card, so you hold the whole fare and owe him the other (100 − cut)% (`txIsCard`/`txFare`/`txOwe`). The totals bar has **Not settled cash** (sum of `txCashNet` on days not settled, all time) and **Not settled card · you owe him** = that owed amount over all days that are not marked Settled (all time); settling a day clears it.   **Taxi spreadsheet import** (`⤒ Import` next to the month arrows; `taxiParseSheet`): reads one of the spreadsheet sections.   - **Profit this month** (`updateAll`) = Σ trip shares of the days in the shown month (each trip × cut %, cards included) − Σ the expenses entered in those days (full amount) − the **Shell payable entries dated in the shown month** (only that month; the **Expenses** box shows the same total, with a tooltip saying how much of it is Shell payable). Other expenses and Credit notes are *not* in the monthly figures. **Net P/L · all time** (`updateAll`) = **cash received (all days) + card received (all days) − all day expenses − Other expenses − Shell payable**, all months (trip income, Credit notes and settled state are not in it). The "Other expenses · all time" and "Shell payable · all time" boxes still show their full list totals.
  - **Expense words** (`TX_EXP_WORDS`, `txHasWord`, `txIsExpense`; used by both picture readers and the diesel stripe): diesel, petrol, fuel, parking, car wash / carwash, tolls, fines, repair(s), service, oil, gas, tyres, **Ramba / Remba**, **Airport Entrance Fee** / Entrance fee. Spelling mistakes match (the number after each word is how many letters it may be out: 0 for short words, 1 for most, more for the long phrases; adjacent words are also joined so "car wash" = "carwash"); short words (≤5 letters) may have a wrong or extra letter but not a missing one. To add a word, add it to `TX_EXP_WORDS` and check place names don't match (see the false-positive list idea in the tests: Cyprus place names and typical trip names must stay trips).
  - **Picture import, more**: sheet rows that start with a date are read by column (`taxiParseTable`: the left amount column is an expense, the next is revenue = your cut %, so the trip is revenue ÷ cut %; one column only → expense words decide); `ocrReadPicture(file, cb, true)` also returns the lines and word positions. A line that starts with a date ("05/03/2026 Makenzie 20") is read (the date is taken off first). The day card reads the picture line by line so trips and expenses keep the picture's own order. Typed / undated lines with a currency sign go to the notes reader, not the table reader.
  - **Currency signs** are accepted before or after a number everywhere (€ £ $, EUR / euro(s) / USD / GBP, with or without a space, `(€5)`, `-€5`): see the `AMT` patterns in `taxiParseTable` and `taxiParseNotes`.
  - The **Not settled cash** and **Not settled card** numbers in the totals bar are blue (`.tx-blue`, a lighter blue in dark mode, a darker one in light mode), also when the card box would otherwise be red for "you owe him"; only the number text is coloured, not the box.
  - **Pages scroll only when needed** (script at the end of the page script): each swipe page keeps 90 px of bottom room (so the "Saved" pill doesn't cover the last item) only when the content really scrolls; otherwise just as much as fits.
- **Birthdays** (opened from Other, stored as `data.birthdays` = `{id, name, date: 'MM-DD'}`, no year; old 'YYYY-MM-DD' entries still work): simple list sorted by next upcoming
  birthday, showing date and "Today / Tomorrow / N days". Add with name + day + month; Enter in any field adds.   printable QR labels per item. Items show as a compact list (one row each: icon, name, LOW tag, − qty +). Stored in IndexedDB on the device; JSON export/import in the menu.

  (REST + EventSource, no SDK) at `/lists/<CODE>/{created,items/<id>,deleted/<id>}`, set via `SHARE_DB` in stock/index.html (project `tp2-list`, europe-west1).

## Backups & safety copies (Sync sheet → "Backup")
- **Download backup** (the main button; the old "Backup now" button was removed because a copy in the same browser storage isn't a real backup) saves all data as `tp2list-backup-YYYY-MM-DD.json` (`{app:'tp2list', version:1, exportedAt, data}`); **Restore from file…** replaces this device's data with it (confirms first, then queues it for sync; the ↩ undo button can step back).
- **Backup reminder** (`updateBackupNudge`, `#backupNudge` under the header): appears when there is data and no backup was downloaded for 7+ days (`tpas2:lastBackup`; "Later" snoozes a day via `tpas2:nudgeSnooze`). (There used to be a red "storage nearly full" bar; it was removed on request — only the Sync-sheet percentage remains.)
- **Storage meter**: the Sync sheet shows `Browser storage: N% used` with a breakdown — your data / safety copies / other (`storageUsed`/`showStorage`, counts localStorage characters against ~5 million; plain text, no warning colour) — and a **Free up space (clear safety copies)** button. The real data always wins over safety copies: `persistData()` (used by every save of `tpas2:tasks`) drops the oldest safety copies one by one when the browser refuses a write, and `takeSafetyCopy` keeps total storage under ~4 million characters (skips the copy if it can't fit). The red **Not saved** badge means even that failed (data bigger than the browser allows). Raising the limit isn't possible in a browser; the real fix would be moving data from localStorage to IndexedDB (not done).
- **Safety copies** (`tpas2:safety` in localStorage, only the newest one is kept, skipped when the data is empty): automatically one an hour (`hourly`: 3 s after opening, when you come back to the app, and a 10-minute timer while it's open, at most one per 55 min; an hourly/daily copy is skipped if the data suddenly shrank to under half the size of the last copy, so a wipe can't replace the good copy), just before a sync update replaces local data (`before sync update`; always on the first sync after joining, otherwise at most every 15 min), and before any restore (`before restore`). The dropdown + Restore button brings one back. Functions: `takeSafetyCopy`, `restoreData`, `fillSafetyList`.
- **Cloud backups** (`cloudBackup`, Sync sheet → Backup → "Cloud backups"): needs a sync code. Every hour while the app is open (3.5 s after opening, on returning to the app, and a 10-minute check; at most one per 55 min) the data (photos left out) is uploaded to `/sync/<CODE>/backups/<slot>` = `{t, json}` with rotating slots `h0..h5` (hour mod 6) and `d0..d6` (day mod 7), so the last 6 hours and 7 days stay in the cloud, away from the device. Skipped when the data is empty or under half the size of the last upload (looks like a wipe) unless **Back up to cloud now** forces it. **Show cloud backups** lists them, **Restore** (confirms, safety copy first) brings one back. Needs no extra Firebase rules (inside `sync/$code`). Only tested with a mock; verify on the real database. The first of these was added after a user lost data on refresh (cause not found).
- Known limit: sync merges per top-level section with newest edit wins, so editing the same section (e.g. Business, which is one section) on two devices at once can drop one device's changes. The safety copy is the net for that.

## Past bugs (fixed — check here first if something looks off)
- Sheets with more than 80 rows stopped at row 80: the row-height fitting loop touched rows that the chunked build hadn't created yet and threw, aborting the render. Any code that loops over `sh.rows` while the grid is built in chunks must stay within `FIRST_ROWS` or guard `rowTh[r]` / `inputs[ref]`.
- A single-quoted JS string containing `'Section 2'` (in the spreadsheet ⓘ tooltip) broke the whole page script for one merge. Always run a syntax check on the page script (extract `<script>` and `node --check`) before merging.
- Sync pull rebuilt data without `ledger`/`spanEvents`, wiping them on every pull.
- Sync push never updated the local timestamp, so the app treated its own saved data as stale and
  overwrote it with an old server copy. (Historical: JSONBin era.)
- Real business data was once hardcoded in the source. It has been removed, but it may still exist in old git history.
- Stray CSS brace, hidden `.stamp-mark` reserving layout space, and a background-color rule blocking the glow.
- Picture / text lines that began with a date were thrown away as junk (digits and slashes looked like a keyboard row); a date prefix is now taken off first. Lines mixing rows with a € amount and plain "Name 20" rows used to put the € rows first: always keep the picture's own order (line by line). Undated lines with a currency sign must not go to `taxiParseTable` (it classifies by x position and made expenses into trips).
- Testing notes: the Claude desktop browser pane throttles timers and does not fire `requestAnimationFrame` while hidden, so test with headless Chrome (`--remote-debugging-port`, drive it over the DevTools protocol) and close it with `Browser.close` (killing it can lose the last localStorage writes); `file://` pages can't load the OCR worker, serve the folder over `http://localhost` for OCR tests; always run `node --check` on the extracted page script.
